## Non-obvious decisions from this session (not fully spelled out in the code)

- **Module split** (ADR-driven, see spec issue #1): `app/db.py` (schema +
  connections), `app/models.py` (plain SQLite CRUD, no business logic),
  `app/services/*.py` (pure functions: `slugs.py`, `passwords.py`,
  `csrf.py`, `markdown.py` — no FastAPI/SQLite imports), `app/routes/*.py`
  (thin HTTP handlers). Keep Post work in this same shape.
- **CSRF**: double-submit via Starlette's `SessionMiddleware`
  (itsdangerous-signed cookie). `ensure_csrf_token(request)` primes a
  session token for any GET that renders a form; `verify_csrf` (a
  dependency) checks it on every POST. Reuse both from
  `app/routes/auth.py` — don't invent a second mechanism for Post routes.
- **Role gate**: `require_user` / `require_admin` dependencies in
  `app/routes/auth.py`, raising `LoginRequired` / `AdminRequired` /
  `CsrfInvalid`, caught by handlers registered in `app/main.py`. Posts need
  a *third* gate shape beyond admin-only: "author owns this Post and it's
  still draft" — that's new logic for T03, probably a small check inside
  the route or a `require_post_owner`-style dependency, not yet written.
- **Slug freeze rule**: generated from title while `status == "draft"`,
  frozen the instant status leaves draft — implemented for Pages in
  `models.update_page`; Posts need the identical rule but their state
  machine has three statuses (draft/pending/published) instead of two, so
  re-check CONTEXT.md's Status section before assuming the Page code
  generalizes directly.
- **Home page singleton**: `pages` table has a partial unique index
  (`idx_pages_single_home` in `app/db.py`, indexing a constant expression
  `WHERE parent_id IS NULL`) so only one root Page can ever exist, plus an
  app-level check-then-insert-then-catch-IntegrityError in
  `models.ensure_home_page()`. Not directly relevant to Posts, but the
  partial-unique-index trick is worth knowing if Posts need a similar
  single-row invariant anywhere.
- **Live preview == static publish, shared templates**: `app/routes/public.py`
  (live, absolute URLs, reads DB directly) and `app/publish.py` (static
  export, relative URLs, writes `site/`) both render `templates/public/page.html`
  via `templates/public/base.html`, differing only in the href/css values
  passed into context. When Posts reach the public site (T05, not T03),
  follow the same pattern rather than writing a third renderer.
- **Code review workflow**: this session ran `/code-review` (medium
  effort) via the `code-review` skill as a background fork before each
  ticket's closing commit, per CLAUDE.md ("Before a commit that closes a
  ticket: post the /code-review findings... as a comment on that issue").
  Both runs found real bugs (crash-on-bad-input, a cascading-delete
  footgun, a race condition) that got fixed before commit — don't skip
  this step for T03.
- **Commit convention**: ticket-closing commits start `T0N:` and end
  `Closes #N`; the usage-ledger/report-notes chore commits are separate,
  smaller commits, not bundled into the ticket commit.
